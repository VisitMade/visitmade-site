# VisitMade marketing site — repository instructions

## Read first

Before significant work, read `AGENTS.md`, `PROJECT.md`, `README.md` and inspect the current static site.

For product claims about VisitMade capability, verify against `VisitMade/platform` rather than assuming the marketing copy is authoritative.

## Product boundary

This repository is the public marketing website for VisitMade. It is not the CRM/platform application and must not become a second source of truth for product functionality.

## Claims and evidence

- Do not invent customer testimonials, performance results, integrations, pricing or compliance claims.
- Clearly distinguish live platform capability from beta/planned capability.
- Product screenshots/examples must not imply real customer results when illustrative.
- Keep accessibility claims evidence-based; implemented accessible patterns do not equal certification.

## Conversion

The current missing commercial piece is an agreed enquiry/demo/contact route. Do not invent a recipient, form destination or booking service.

## Engineering

Keep the static site simple unless a real requirement needs server functionality. Run the repository's check/build commands for material changes.

## Documentation is part of done

Update `PROJECT.md` when the commercial CTA, launch state, product positioning, analytics/enquiry setup or current milestone changes.

## Handoff

Read `PROJECT.md` first and update it last.
